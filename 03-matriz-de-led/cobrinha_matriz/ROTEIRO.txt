//2. MOSTRA (o show de voces): o array vai pro fio
//
//O QUE O DATASHEET PEDE (tabela "Data transfer time", tolerancia +-150 ns)
//    bit 0: 0,40 us em HIGH, 0,85 us em LOW
//    bit 1: 0,80 us em HIGH, 0,45 us em LOW
//    bit inteiro: 1,25 us (+-600 ns)
//    reset: LOW por mais de 50 us, ai todos os LEDs mostram o que guardaram
//
//POR QUE O digitalWrite NAO SERVE
//16 MHz = 62,5 ns por ciclo. 0,40 us = 6 ciclos. O digitalWrite procura o pino numa
//tabela, desliga o PWM e so depois escreve: dezenas de ciclos, uns 5 us no Mega.
//Mais lento que o bit inteiro.
//
//O QUE FAZER ENTAO
//O digitalWrite, no fim, escreve 1 bit no registrador PORT. Voce pula o caminho e
//escreve no PORT direto, como ja faz com TCCR1B e TIMSK1.
//  - Antes do laco, ja com noInterrupts(), calcula dois bytes:
//        hi = PORT com o bit do pino em 1      (mascara com |  e  <<)
//        lo = PORT com o bit do pino em 0      (mascara com &  e  ~)
//    No laco e so PORTx = hi ou PORTx = lo: uma escrita de 2 ciclos.
//  - noInterrupts() no comeco e interrupts() no fim: a ISR do Timer1 (e o Timer0 do
//    millis) no meio de um bit esticaria o HIGH e o LED leria errado.
//  - Laco de fora: os NLEDS * 3 bytes. Laco de dentro: os 8 bits, do 7 pro 0.
//    Testar o bit 7 e depois deslocar o byte (<< 1) e o mesmo que o shot faz com o >>.
//
//A ESPERA: nop
//Mesmo escrevendo no PORT, o C sozinho e rapido demais: ligando e desligando sem
//esperar, o HIGH dura 3 ciclos (187 ns, abaixo do minimo). Pra esperar uma quantidade
//EXATA de ciclos existe o nop, instrucao que nao faz nada por 1 ciclo (62,5 ns):
//    #define NOP asm volatile("nop")
//Formato do bit, em C:
//    fio HIGH
//    NOP ... (quantos?)
//    se o bit for 0: fio LOW
//    NOP ... (quantos?)
//    fio LOW
//    desloca o byte
//Custo em ciclos pra fazer a conta: escrita no PORT = 2, nop = 1,
//teste do bit = 1 se nao pula a escrita, 3 se pula. Monte no papel a tabela de
//ciclos do caminho do bit 0 e do bit 1, escolha os nops e deixe a tabela aqui no
//comentario. O laco (contar bit, voltar) gasta mais uns 4 ciclos no LOW.
//
//RESET (pagina 4 do datasheet, "Data transmission method")
//Um "Data refresh cycle" = os 64 x 24 bits seguidos, sem pausa, e depois o
//"reset code": fio em LOW por >= 50 us. So no reset os LEDs trocam de cor juntos.
//Depois do laco: fio em LOW e espera mais de 50 us. delay(1) (1 ms) serve e ja foi
//usado em aula; o tempo extra nao estraga nada.
//
//CASCATA (pagina 4, "Cascade method")
//O seu codigo so manda no D1 (DIN do primeiro LED). O LED 1 fica com os primeiros
//24 bits e repassa o resto pelo DO; o LED 2 fica com os proximos 24, e assim por
//diante. Por isso o primeiro trio do array e o LED 0 da fila.
//
//CONFERIR O QUE O COMPILADOR GEROU (a prova de que a conta vale):
